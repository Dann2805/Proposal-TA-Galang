\section{Pengumpulan dan Persiapan Data}

Tahap ini bertujuan untuk memperoleh data visual yang merepresentasikan kondisi operasional ritel komersial secara nyata, yang nantinya digunakan sebagai input sistem sekaligus dasar validasi pengujian.

\subsection{Sumber dan Karakteristik Data}
Data diperoleh secara langsung melalui perekaman sistem kamera pengawas (CCTV) di dua lokasi area komersial ritel. Untuk mendapatkan tingkat kepadatan dan tantangan oklusi yang representatif, pengambilan data dilakukan pada jam operasional sibuk (\textit{rush hour}). Durasi setiap sampel video dibatasi antara 10 hingga 15 menit. Pengambilan data mempertimbangkan beberapa variasi kondisi, meliputi perbedaan tata letak etalase, variasi pencahayaan ruangan, tingkat kepadatan antrean, serta sudut pandang elevasi kamera (\textit{oblique angle}). Seluruh proses perekaman dilakukan secara anonim tanpa melibatkan modul ekstraksi fitur wajah demi mematuhi etika privasi.

\subsection{Pembuatan Data Acuan (\textit{Ground Truth})}
Video mentah yang telah dikumpulkan kemudian dianotasi secara manual untuk membentuk data acuan (\textit{ground truth}). Anotasi dilakukan dengan mencatat stempel waktu (\textit{timestamp}) aktual pada level bingkai (\textit{frame-level}) untuk mendata tiga parameter utama: (1) total volume pengunjung yang melewati garis virtual kasir, (2) durasi waktu singgah riil per individu di area etalase, dan (3) durasi waktu antre per individu. Data acuan ini menjadi standar emas absolut untuk mengukur margin galat sistem pelacakan otomatis nantinya.

\section{Lingkungan Pengujian dan Spesifikasi Sistem}

Dalam menjalankan simulasi dan pengujian algoritma \textit{Multi-Object Tracking} (MOT), penelitian ini membutuhkan spesifikasi perangkat keras dan perangkat lunak yang memadai guna menjaga stabilitas akselerasi komputasi \textit{Deep Learning}. 

\subsection{Perangkat Keras (\textit{Hardware})}
Perangkat keras yang digunakan untuk menjalankan eksperimen deteksi YOLO11 dan pelacakan berbasis \textit{bounding box} adalah satu unit komputer jinjing (\textit{laptop}) dengan spesifikasi sebagai berikut:
\begin{itemize}
    \item \textbf{Prosesor (CPU):} Intel Core i7-12650H. Bertugas menangani beban pemrosesan logika komputasi sekuensial, manajemen \textit{thread}, dan eksekusi skrip ekstraksi metrik spasial.
    \item \textbf{Unit Pemroses Grafis :} NVIDIA GeForce RTX 4050 Laptop GPU (\textit{Mobile}). GPU ini berperan krusial dalam akselerasi komputasi paralel dan pemrosesan \textit{frame} video secara konstan, sehingga evaluasi parameter \textit{System FPS} pada masing-masing algoritma dapat diukur secara objektif.
    \item \textbf{Memori :} 16 GB. Kapasitas memori ini dialokasikan untuk memastikan kelancaran pemuatan bobot (\textit{weights}) model detektor, penyanggaan (\textit{buffering}) \textit{frame} memori video, serta kelancaran operasional sistem secara keseluruhan.
\end{itemize}

\subsection{Perangkat Lunak (\textit{Software})}
Lingkungan perangkat lunak yang digunakan dalam pengembangan dan pengujian sistem analitik ini meliputi:
\begin{itemize}
    \item \textbf{Sistem Operasi dan IDE:} Sistem operasi Windows 11 yang digunakan bersama lingkungan \textit{Integrated Development Environment} (IDE) Visual Studio Code (VS Code) untuk penulisan dan eksekusi kode.
    \item \textbf{Pustaka (\textit{Library}) Utama:} Python 3 dengan pustaka PyTorch (untuk \textit{tensor backend}), OpenCV (untuk ekstraksi \textit{frame} video dan visualisasi \textit{polygon/tripwire}), serta model YOLO11 dari Ultralytics.
    \item \textbf{Modul Pelacakan:} Repositori \textit{BoxMOT} yang menyediakan antarmuka integrasi untuk menjalankan algoritma ByteTrack, BoT-SORT, OC-SORT, dan Deep OC-SORT.
\end{itemize}

Alur kerja arsitektur sistem pada Gambar \ref{fig:pipeline_tbd} diuraikan sebagai berikut:
\begin{enumerate}
    \item Sistem menerima input berupa bingkai (\textit{frame}) video ritel secara sekuensial.
    \item Setiap bingkai diproses oleh model detektor YOLO11 untuk melokalisasi target manusia dan menghasilkan koordinat kotak pembatas (\textit{bounding boxes}).
    \item Sekumpulan kotak pembatas mentah tersebut diteruskan ke modul algoritma pelacak (salah satu dari ByteTrack, BoT-SORT, OC-SORT, atau Deep OC-SORT).
    \item Algoritma pelacak melakukan asosiasi data antar-bingkai menggunakan matriks jarak (\textit{Intersection over Union} / IoU) dan/atau filter Kalman untuk menautkan deteksi pada bingkai saat ini dengan riwayat jejak (\textit{tracklets}) sebelumnya.
    \item Sistem mengeluarkan output final berupa kotak pembatas yang telah dilengkapi dengan nomor identitas (ID) unik dan konsisten untuk setiap pengunjung.
\end{enumerate}

\section{Ekstraksi Metrik Perilaku Konsumen}

Hasil keluaran berupa koordinat target beserta ID unik dari sistem MOT tidak dapat langsung dibaca sebagai metrik bisnis. Oleh karena itu, diperlukan modul logika tambahan untuk mengekstraksinya:
\begin{itemize}
    \item \textbf{Penghitungan Pengunjung (\textit{People Counting}):} Dihitung berdasarkan logika persilangan garis virtual (\textit{tripwire}). Jika titik tengah koordinat kaki target dengan ID tertentu memotong garis dari arah A ke B, maka sistem akan menambahkan hitungan masuk.
    \item \textbf{Waktu Singgah (\textit{Dwell Time}):} Dihitung dengan mendefinisikan poligon area ketertarikan (\textit{Region of Interest} / ROI) pada etalase. Sistem merekam indeks \textit{frame} saat ID tertentu masuk ke dalam poligon ($t_{\text{masuk}}$) dan indeks \textit{frame} saat ID tersebut keluar ($t_{\text{keluar}}$). Durasi dikonversi ke detik murni berdasarkan \textit{frame rate} asli video untuk mencegah distorsi waktu akibat penurunan beban komputasi.
    \item \textbf{Waktu Antre (\textit{Queue Time}):} Dihitung dari akumulasi waktu saat suatu ID berada di dalam poligon area kasir dengan kondisi perpindahan koordinat piksel yang sangat lambat di bawah ambang batas kecepatan tertentu (\textit{statis}).
\end{itemize}

\section{Pengujian dan Evaluasi Sistem}

Pengujian dan evaluasi dilakukan untuk mengukur kinerja sistem secara komprehensif, mulai dari keandalan pelacakan di tingkat piksel hingga akurasi data bisnis.

\subsection{Pengujian Kinerja Pelacakan Akademik}
Pengujian ini bertujuan untuk mengukur ketangguhan algoritma dalam menjaga konsistensi identitas target di bawah tekanan oklusi visual. Parameter yang digunakan bertumpu pada metrik CLEAR MOT, khususnya:
\begin{itemize}
    \item \textbf{\textit{Multi-Object Tracking Accuracy} (MOTA):} Menilai tingkat kesalahan deteksi (positif palsu, negatif palsu) dan perpindahan identitas (\textit{ID switches}).
    \item \textbf{\textit{Identification F1-Score} (IDF1):} Mengukur seberapa lama algoritma mampu mempertahankan satu ID yang sama pada target yang benar secara berkesinambungan.
    \end{itemize}

\subsection{Pengujian Tingkat Galat Metrik Bisnis Terpadu}
Pengujian ini mengevaluasi kinerja sistem setelah modul ekstraksi perilaku diintegrasikan. Output sistem dibandingkan secara langsung dengan \textit{ground truth} manual untuk mengukur penyimpangan (\textit{error}) di dunia nyata. Metrik galat yang diukur meliputi \textit{Mean Absolute Error} (MAE) untuk deviasi durasi \textit{dwell time} dan antrean (dalam satuan detik), serta \textit{Mean Absolute Percentage Error} (MAPE) untuk persentase galat pada penghitungan jumlah orang.

\subsection{Analisis Korelasi Statistik}
Tahap evaluasi akhir dilakukan dengan menganalisis hasil pengujian menggunakan uji korelasi statistik (Pearson atau Spearman). Analisis ini digunakan untuk mengetahui derajat hubungan empiris antara tingginya skor metrik akademik (MOTA/IDF1) dengan rendahnya nilai galat (MAE/MAPE) pada metrik perilaku konsumen di lapangan. Hasil evaluasi ini akan menjadi dasar identifikasi keterbatasan sistem serta penarikan kesimpulan penelitian.
